# Radmir Farm Bot — исправленная версия v3.3

База: работающая ветка **v3.2**. Это НЕ публичный v4. Файлы: `bot.py`, `requirements.txt`.

## Что исправлено

1. **Настроить цены** теперь открывает список товаров, позволяет выбрать товар и задать цену **за одну единицу**. При добавлении количества цена умножается автоматически. Старые закупки не пересчитываются.
2. **Склад**: кнопки «Новый товар», «Удалить товар», «Вернуть скрытые». Новый товар добавляется по имени, после чего ему надо назначить цену. Удаление скрывает позицию, не удаляет историю списаний и закупок. Скрытые товары можно вернуть. Стандартные материалы можно скрыть из меню, но внутренние правила посадки продолжат их учитывать.
3. **Гербицид**: при **заполнении огорода до 20 растений** автоматически списываются **5 шт.** Это нормативный расход, а не фактическое наблюдение, и кнопки поштучного гербицида убраны. При неполной посадке расход не производится.
4. **Рост и полив**: отдельные накопленные секунды роста для каждого куста; время засчитывается только до срока обязательного полива. После просрочки процент стоит на месте, после очередного полива продолжается. Кнопка отмены полива возвращает и предыдущий накопленный прогресс. После посадки считается, что первичный полив выполнен в момент отмеченной посадки (как и в прежней версии).
5. Расход лопаты теперь считается при заполнении огорода до 20 кустов, в том числе если кусты добавлялись несколькими действиями.

**Особенность старых растений:** точную историю просроченных поливов задним числом восстановить нельзя. При переходе их накопленный рост будет оценён консервативно (не более одного интервала до последнего полива); для точного тестирования лучше использовать свежую посадку. Новые растения работают по новой системе.

## Установка на Bothost через GitHub

1. Остановите один работающий экземпляр бота на время обновления.
2. В существующем репозитории GitHub замените `bot.py` и `requirements.txt`, не публикуя токен, `.env` и файл `.sqlite3`.
3. В панели Bothost обновите приложение из GitHub и проверьте реальные логи, потом `/start`.
4. Для устойчивого сохранения SQLite после обновлений необходимо использовать постоянный том и переменную `DB_PATH` с действительным путём тома у провайдера. Без этого данные могут сбрасываться при пересоздании контейнера.
5. **Не запускайте одновременно на Replit и Bothost** с одним токеном.

## Статус проверки

Проверен синтаксис Python. Выполнены автономные функциональные тесты работы SQLite и функций подсчёта (без живого Telegram). Полноценную проверку в Bothost/Telegram нужно провести после установки.
